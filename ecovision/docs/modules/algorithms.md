## 第一版滤波与参数

真实噪声与响应未测，所以选型仅基于可重复的明确合成信号，不声称实板最优。比较原值、三点中值、三点均值、一阶低通 α=0.25；比较程序见 `tests/algorithms/evaluate.py`，数据与数值见 `evidence/filter_comparison.csv` 和 `metrics.json`。三点中值兼顾孤立尖峰与阶跃延迟，用于温湿度及光敏**评价**。控制沿用经过有效性／范围检查的**原始温度**，不静默更改 A04 时序。

| 参数 | 默认／依据 | 延迟与恢复 |
|---|---|---|
| 温度量程 | -4000..8500（0.01℃），沿公共契约 | 超界立即 invalid，不先滤波 |
| RH／光敏／人数范围 | 0..10000／0..65535／0..20 | 按各自来源单位检查，不共享缩放 |
| 温度／RH 过期 | 10000 ms；温度来自契约，RH 是本地暂定参数 | 年龄达到阈值即无效；RH 尚非公共字段扩展 |
| 光敏过期 | 2000 ms，本地暂定，假设未来 100 ms 独立采样 | 老原包周期不满足时应显式过期，而不是放宽或刷新旧样本 |
| 视觉过期 | 5000 ms，沿契约 | 单帧无效或到时立即 UNKNOWN，中断确认 |
| 中值窗口 | 3 个有效、新时刻样本 | 首两个有效样本直接透传且 stable=false，第三个起 stable=true；stable 只指窗口就绪，不证明物理稳定 |
| 跳变诊断 | 相邻有效温度 >2℃、RH >10%RH、光敏 >10000码 | 仅 EV_JUMP 标记，不因跳变自动拒绝；阈值未由真实斜率验证。保留原值，防止掩盖故障 |
| 人数 | 不作数值中值滤波 | 唯一一次占用确认：连续 3 个有效正帧；连续有效 0 且满 30 s 才无人 |
| 数字消抖 | 连续相同电平 30 ms | 第一次电平满时长才变为已知；反复跳变重计时；无事件双触发逻辑 |

中值在稳定采样、无缺测时对永久阶跃引入约一个采样周期延迟；1 s 温湿度采样即约 1 s，100 ms 光敏采样即约 100 ms。不规则采样由下一有效样本时间决定；掉线时没有有限的滤波响应保证，应转 UNKNOWN。暖机到完整三点窗口需要两个采样间隔。无效或过期清空窗口；下一有效样本重新透传、重新暖机，恢复不会带入旧中值。

last_attempt 保留最近递交的原始样本，包括超界、无效、重复与异常时间；raw／filtered／at_ms 保留最近有效样本及其原采样时间。无新样本 present=0，不能反复把缓存值封成 present=1 且更新 at_ms。重复时间不刷新任何有效时间或占用帧数；旧／未来时刻拒绝并留诊断。新失败样本立即使当前有效性失效，但不改写最后有效时间。输入 age 超限时，即使 valid=1 也不能接纳为新鲜。

常量暂保留在模块内；正式 AUTO 的阈值、时效和优先级来自公共 1.0.0，修改前必须由总控统一更新。光敏和 RH 本地过期、跳变诊断为暂定工程参数，需要实际日志验证。

## 原型舒适需求定义

分别输出 thermal（UNKNOWN/COLD/SUITABLE/HOT）、humidity_need（UNKNOWN/DRY/SUITABLE/WET）、light_need（当前固定 UNKNOWN）、occupancy 及 vision_valid。无综合分数，不进行权重抵消。湿度不修正热需求分数，也不自动触发循环风扇。

可配置 `EvState.comfort` 的描述性默认：温度 <20℃ 偏冷、20..不足28℃ 适宜、≥28℃ 偏热；RH <30% 偏干、30..70% 适宜、>70% 偏湿。20℃／30%／70% 是原型可解释标签的暂定值，28℃与已有启扇阈值对齐；均不是人体舒适标准、健康界限或正式模型。需使用者反馈与真实环境记录验证。改动描述性标签不会改变 27/28℃控制逻辑。

人数只作占用门控，不估计热负荷。未实现 PMV/PPD；本原型缺平均辐射温度、空气流速、着衣量、代谢率等测量或可靠假设，亦未开展正式模型适用性和标准核验；后续若引入，须另行查阅可靠原始资料与验证，不把当前标签叫作 PMV 或 PPD。

`degraded_mask` 按 TEMP/RH/LIGHT/VISION 位标记无效、暖机或诊断；`simulated_mask` 标记最后有效数据是否模拟；每路 `source` 标识本地来源，可由集成登记 1=板载、2=视觉、3=注入（测试夹具使用 source=1、simulated=1，表示合成板载流）。`affected_mask` bit0=风扇、bit1=LED，标记 AUTO 感知能力缺失。温度无效影响风扇；视觉未知影响两路。光敏未标定由 EV_REASON_LIGHT_UNCALIBRATED 明确说明，仅限制光需求评价，当前 LED 仍按占用规则。

## 与现有控制的衔接

本模块是纯计算，未调用 HAL、GPIO、PWM、网络、时钟或动态分配。ev_step 输入已经仲裁的 mode 与实际逻辑输出，返回 apply_mask 和建议；每周期从 STM32 当前输出起算，防止手动后回自动使用过时输出。

- AUTO：确认有人 LED=1；原始有效温度≥28℃连续5秒建议风扇1，≤27℃连续5秒建议0，中间保持。新反向或回差区输入中断持续确认；无效／过期也中断。正常温控相邻反向动作至少5秒，二值限幅0/1，无额外速率／PWM参数。无人关断和故障关断不受此间隔阻挡。
- 有效 0 帧确认前维持前一占用状态，不能将单帧漏检当无人；无效帧直接 UNKNOWN。串口会话、CRC、seq、旧帧过滤在上游；上游只做解析和验证，不再叠加另一套3帧／30秒。若已有人数状态机，STM32应在两者中选一个唯一实现，不串联。
- 感知失效先保持受影响输出；温度失效时有效占用仍能开 LED。视觉 UNKNOWN 时两路保持；连续任一关键感知故障≥60秒，两路关。启动 GPIO 必须由 STM32先置0；算法初始化无历史。故障恢复需重新进行温控确认，视觉失效后重新3帧／30秒。
- REMOTE：apply_mask=0，算法不接管；LOCAL_OFF：建议两路0。未知 mode 保守让权。短长按、远程合法性、租期、epoch、防重放与电气保护由 STM32唯一管理。远程租期到期后将 mode=AUTO 传入，算法才恢复建议；本模块不判断远程命令是否可信。
- 断网：无网络输入依赖，本地继续计算；既有租期、到期与本地关闭仍由控制权管理器执行。重启重新 ev_init，STM32 生成新 boot_id、清旧租期，不能恢复旧算法状态或旧远控。

所有 reason 位均为内部诊断，不可直接塞进公共 faults。公共消息仅输出契约认可的 SENSOR_FAULT／VISION_FAULT／NET_OFFLINE；invalid 值映射 null。公共 temp_c 推荐继续使用有效原始温度，避免把“滤波评价温度”悄然替代当前遥测语义。

## STM32 接口与集成步骤

1. 工程 App 分组加入 `algorithms/ecovision_algorithm.c`，头文件搜索路径加入 `algorithms/`。保留现有驱动。静态分配 `EvState`，启动调用 `ev_init`。输入结构每轮清 present，只有实际新采样设置1。
2. 独立采集任务建议温湿度1s、光敏100ms；这是新调度建议，尚非实测频率。采样成功或失败都携带 STM32 本地单调采样完成时间；温度／RH 若不同转换应各有时间。不能用 MQTT 完成时间、UTC或 K230 uptime 替代本地 at_ms。
3. UART验证器接收新的匹配会话／seq帧时，以本地接收时间提交 count／valid。每次接纳新会话后，在其首帧EV1前由唯一控制任务调用 `ev_reset_vision`；该函数清视觉频道／占用确认／温控持续确认，不清其他感知、控制权或故障计时。无效帧提交 valid=0。坏CRC／旧帧丢弃不刷新时间。
4. 唯一控制任务每≤100ms执行 ev_step。数据在任务之间用队列或一致性快照交换；不要从ISR并发调用。所有状态单一所有者，不能同时由网络任务写。
5. 实体按钮首先按统一控制权管理器更新模式和撤销租期，再填 mode／fan_actual／led_actual。ev_debounce仅在已有驱动未消抖时选用一次；长按2s和释放动作由嵌入式处理。
6. 驱动只应用 apply_mask 标记的输出；保护逻辑和控制权变化在真正写硬件前再次检查。LED=1映射一个已验档位；现有 AppLed_Run 仅台架入口，需要嵌入式提供任务安全的亮灯命令接口，并将台架串口命令接入统一模式，避免绕过 LOCAL_OFF。
7. 从 EvChannel读取最后有效值／age／source／simulated及last_attempt；从未有效 has_value=0时对外 age=null。旧值可保留用于日志但 valid=false时不能当有效遥测。湿度／光敏额外年龄留模块日志，不自行新增公共字段。
8. 开始 A03/A04/A12 硬件记录：原始／滤波／时间／有效性／错误、占用、建议、实际输出、mode、网络、设备版本和配置。验证驱动极性、启动关闭、真实动作和时延后再计 M1。

整数 API：TEMP 单位0.01℃，RH单位0.01%RH，光敏read_u16原码；HAL 原生12bit ADC不可未经声明直接混作同一尺度。uint32时间使用模差，支持正常计时回绕；任何两个比较时刻间隔必须<2^31ms，超过该不确定间隔应重新初始化并安全恢复，不支持乱序时间流或跳跃几个月。循环任务仍必须持续调度，不能只在MQTT消息时执行。

## 离线回放与验证

执行 `powershell -NoProfile -ExecutionPolicy Bypass -File tests/algorithms/run.ps1`；再执行 `tests/algorithms/build-arm.ps1`。前者编译／运行真实C实现并生成回放，后者编译独立Cortex-M4对象；二者均不烧录。工具路径写在脚本，可按集成机修改。

CSV每行18个整数，头行可选：

```text
now_ms,temp_at,temp_c100,temp_valid,rh_at,rh100,rh_valid,light_at,light_raw,light_valid,vision_at,count,vision_valid,mode,fan_actual,led_actual,source,simulated
```

valid=-1表示本行无新样本，0新失败，1新有效；mode=0/1/2对应AUTO/REMOTE/LOCAL_OFF；actual=-1仅回放工具使用，表示沿用前一建议模拟执行，不证明真实执行；0/1为明确外部输出。真实记录要使用实际状态并将simulated=0，按实际来源填source；非同时采样需用各自at，不复制本行now。控制保护、租期和执行器反馈记录需附独立日志，CSV不模拟合法命令处理。

入口 `tests/algorithms/build/replay.exe` 从stdin读CSV，stdout写逐行状态。输出含各路原始／滤波／valid／age／stable／reason与来源标记；输入CSV本身保留失败／超界的原始值，C状态last_attempt也保留它们。错误格式返回非零。相同输入运行两次字节一致，SHA256在metrics.json。

## 资源和限制

MSVC主机测量 EvState=276B、EvInput=72B、EvOutput=14B、EvDebounce=8B；状态内含四路最近尝试原始记录。单设备一套状态／输入／输出共362B，两个数字消抖再16B，不含RTOS栈、队列和驱动。Cortex-M4对象的.text/.rodata明细见 `arm_resources.json`，不等于最终固件体积。无heap、无浮点、无阻塞调用，每步固定4路、有界3值比较，O(1)。CPU周期／最坏执行时间和实板任务栈尚未测量，不能用对象编译代替资源实测。

不能识别所有量程内故障、卡死值、安装位置偏差或电磁干扰；不能用温湿度断言人体舒适；不能由单点光敏推断工作面lx；不能凭计数推断热负荷；没有窗户开到位、转速、机械效果和红外目标反馈。本版公开规则保持不变，所以不宣称控制误动作优于原始规则；滤波收益仅限合成评价数据。
