# EcoVision 2026年11月20日任务安排

今天是本地视觉闭环M1关口。首要交付为同一运行版本的K230人数→STM32→实际LED/5V风扇，并验证失效与人工接管。4G上报与远控关口仍为11月24日；25日冻结、27日8小时、29日交付。总预算≤5000元，今天不安排新增采购。

## 计划依据与当前缺口

已读取PROJECT、INTERFACES、ACCEPTANCE、11月19日日报、TB6612记录，并只读查看“模型训练与k230部署”和“检查 EcoVision STM32 工程”最新两轮。视觉聊天最新报告多人版已部署、单一七人布局约14—15FPS，随后用户确认双板“还没接”；当前识别脚本仍没有UART功能。总控核对多人版脚本和selected产物存在，不能据单布局结果判0—15全部通过。风扇文档与聊天仍缺新版本烧录/实物通过证据。

本文件安排后续工作，不认领代码、软件或硬件已通过。今天没有向其他聊天发指令，也未改公共契约或模块源码。

## P0 第一阶段 固定版本与接线

负责人：用户实物操作，视觉与STM32模块分别提供配置，总控核对。

- 保存当前K230脚本/模型、F413ZH固件及MicroPython联网版本的可恢复副本，记录版本与启用入口。
- 本地闭环优先在现有C/HAL灯/风扇工程上继续，旧MicroPython联网结果单独保留。双方确认后，后续4G也在最终交付版本中联调，不能来回换镜像拼接验收。
- 核实K230具体板型、UART实例和排针丝印及电平，再确定TX/RX/GND；STM32候选为USART2 PD5/PD6。不要仅凭旧GPIO5/6候选编号接线。
- 核对TB6612、灯环的最新资源表与实际线束。独立电源、共地及默认关闭按当前已确认接法检查。

完成标准：一张实际接线表、一套明确的脚本/模型/固件版本，不存在同一针脚重复占用。建议首个工作时段完成。

## P0 第二阶段 分两条线准备

### STM32与负载

负责人：“检查 EcoVision STM32 工程”。

1. 烧录已核对版本的TB6612固件，确认上电与复位默认F0。
2. 实物验证F0停止、F1—F4各档能否由静止起转、转向与异常，区分串口回执、PWM和实际旋转。
3. 灯环0—4与风扇交替操作，确认无误触发或复位。
4. 加入正式视觉接收与唯一控制入口，沿用CRC/会话/序号、有效性、回差与按键优先级。

完成标准：实物启停记录、固件构建与烧录日志、接收固定正式帧后可驱动对应负载。固定帧阶段标记为模拟输入，不计真实视觉闭环。

### K230与串口

负责人：“模型训练与k230部署”。

1. 先选目前可在板端运行且在联调视场内稳定的模型；保留V4与多人版回滚，不以新一轮训练作为接线前置条件。
2. 把实际推理结果接入已有正式协议入口或同等实现：STM32发EVQ、K230回EVH，再每秒发EV1。
3. UART日志与调试print使用独立路径，不能把count/FPS文字当作正式人数帧。
4. 先验证双向收发、0/1人数、有效标记与握手，再覆盖多人。异常和超范围结果不得静默裁剪成合法人数用于控制。

完成标准：实际两板收发日志可关联EVQ→EVH→EV1，模型运行和正式串口输出存在于同一脚本入口。

两条准备线可由各模块同时进行；用户实物操作先保证负载台架可用，随后立即接双板。

## P0 第三阶段 合成真实本地闭环

负责人：视觉、STM32、算法与用户，总控验收。

- 实际识别连续3个有效正人数帧后确认有人并开灯；连续有效0帧满30秒后确认无人并关两路。
- 有人时，真实有效温度≥28℃连续5秒开风扇、≤27℃连续5秒关，中间保持。温度注入只能记为逻辑测试，真实温控结果另列。
- 断开视觉UART，5秒达到失效条件后人数/占用显示未知，不能当无人；按既定60秒关键故障规则处理并测试恢复重新确认。
- 实体长按进入LOCAL_OFF，两路关闭；短按回AUTO，不能只用PC串口代替实体操作验收。
- 上述场景先逐项通过，再连续运行至少30分钟；按ACCEPTANCE记录覆盖次数。保留采样时刻、有效性、原始帧、模式、GPIO输出和独立实物观察。

小人沙盘与真人测试分别记录。小人闭环跑通可证明该场景工程链路，但A02/A03中的真人精度及进出测试若未做，仍列未验，不静默改成通过。
